# Character acting and rendering

`Renderer/acting.mjs` contains six original authored keyframe clips: idle, listening, thinking, speaking, greeting and touch. They drive the normalized VRM pelvis, torso, neck, head, upper/lower arms, wrists, finger joints and eye target. Pelvis weight shifts, small turns and dips now engage the legs through `Renderer/stance.mjs`. These are original authored motions with analytic leg IK, not motion capture or the final reference-quality animation set.

- Both feet retain their initial avatar-local position and orientation. The normalized two-bone leg solver bends the knees forward, preserves segment lengths and lowers the pelvis when a shift would otherwise overextend the far leg. Foot contacts follow the parent turntable; they do not stay fixed to the browser world when the character turns.
- Pelvis offsets scale with character height and remain bounded. Each frame starts from the captured leg rotations, preventing accumulated drift. Missing leg bones disable the entire stance layer. Reduce Motion blends back to the initial quiet stance through the same acting controller.

- Smoothstep interpolation keeps adjacent keys and loop seams continuous. State changes blend from the last displayed pose, including an interrupted transition. Listening/thinking/speaking interrupt a decorative greeting or touch reaction.
- Greeting is a one-shot wave with authored wrist reversals. A separate touch nod has a cooldown. Repeated native idle updates do not restart the greeting.
- Character touches are ray-tested against the currently posed model. Background taps, vertical/horizontal drags, cancelled pointers and additional fingers do not trigger the touch clip. Drag rotates the parent turntable; VRM0 orientation correction remains intact.
- Reduce Motion settles into a quiet pose and disables decorative touch/greeting and drag rotation. Blinks and actual-audio mouth feedback remain available. Eye blinks have uneven intervals.
- Body clips do not invent mouth motion: the existing audible-PCM amplitude and 180 ms stale-sample cutoff still control the jaw. Phoneme articulation remains unfinished.
- Native code requests a 30 fps cap under Low Power Mode or serious/critical thermal state; normal cap is 60. Thinking and Reduce Motion also cap at 30. These are scheduling limits, not measured iPhone frame rates or energy claims.
- The canvas pauses while the scene is inactive or settings/commands cover it, then resumes the same loaded model. No new network access or conversation/credential bridge data is introduced.
- Facial morph targets are combined by VRM expression before the first render, using the installed three-vrm utility. The regression probe compares every preset plus mixed blink/mouth/smile poses against the original model's vertex positions and normals; the probe is not bundled into the app.
- WebGL context loss clears readiness and the last speech sample, then suspends animation/rendering until the restored context triggers a local scene reload. Readiness is reported again only after an actual rendered frame; the native host reapplies its current state after navigation completes. Loss listeners are installed before model loading.

Validation: fourteen renderer unit tests exercise loop seams, one-shot return, rapid interruption, gesture priority/cooldown, Reduce Motion, matching elapsed-time poses at 30/60 fps, leg contacts in both VRM facing conventions, transformed/scaled parents, unreachable input and incomplete rigs. Browser tests exercise the real VRM, all four sustained states at three viewport sizes, a three-quarter view, hit-tested touch and drag/background rejection, pause/resume, and explicit model-load errors. A separate test-only probe samples all six stance clips on the real model and checks both normalized and retargeted raw feet, orientation, knee direction and bone lengths. Native iOS evidence and remaining gaps are recorded in VERIFICATION.md.

The workflow's real-inference check defaults to enabled. For changes confined to character/UI code it can be disabled after verifying the local model catalogue, inference code and runtime are unchanged from a previously successful inference run.
